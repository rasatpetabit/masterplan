Purpose

Make masterplan understand operator intent before designing (interview + fresh-context critic), record intent-first goals (goals v2), and drive every run to a live, confirmed, archived completion (deploy stage, completion classes), with the config plane, inert-knob guard, seed-time overlap check, and context watch that the spec requires.

Problem

Rev 14 of the spec passed four cross-vendor panels; its acceptance list is spec.md section 11. The plan below is seven parallel-drafted subsystems merged deterministically; the integration subsystem owns the shared CLI, schema, sequencer, and docs files.

Solution

Every wave implements the spec; the post-wave stage below is NOT a plan task (spec A33 and section 10.1) and cannot be rendered by the installed 9.10.0 plan renderer, so it is stated here, in WORKLOG.md, and as a durable `pre_finish_stage_required` event on this bundle's events.jsonl (recorded 2026-09-03 via the pinned v9 `mp event`; superseded by a v2 event with the split rule). After the LAST wave completes, the orchestrator executes the live v9-to-v10 bootstrap stage from the branch with `node scripts/bootstrap-v10.mjs` (status, arm, run the printed command from MAIN, record) through pre-publish verify/review/assessment, release, push, CI, install of both surfaces, publish acknowledgement, and the GitHub PR merge. Two preconditions bind the finish: (a) `mp finish` is invoked only after `node scripts/bootstrap-v10.mjs status` reports the pass complete through `surfaces_live`, and `required_successor {slug: v10-validation}` has been recorded via the pinned v9 `mp event`; (b) the `gate` step (`arm --step=gate`, the rebase, `record --step=gate`) executes inside the branch_finish handling before `--choice=merge`, and is the only bootstrap step permitted after finish begins. Under the installed 9.10.0 sequencer the durable enforcement is the finish-time goal check, where G6 is assessed live and a skipped stage lands at goals_unmet rather than archiving.
